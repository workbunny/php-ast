# 版本兼容性承诺

php-ast 当前处于 **0.x 阶段**——与 Zig 语言自身的版本策略一致：**暂不承诺
1.x 稳定性**。破坏性变更是 0.x 的常态，但必须**被记录、被预期**，而非
静默发生。

## 版本语义

php-zig 遵循 `MAJOR.MINOR.PATCH`（`x.y.z`）。在 0.x 阶段的特殊约定：

| 版本段               | 承诺                                          | 示例                |
|----------------------|-----------------------------------------------|---------------------|
| **z（PATCH）**       | **发布不破坏 API**。仅 bugfix、内部重构、文档 | `0.11.0 → 0.11.1`   |
| **y（MINOR）**       | **可能破坏 API**。新功能 + 破坏性变更         | `0.11 → 0.12`       |
| **x（MAJOR，即 0）** | 暂不承诺 1.x 稳定                             | 何时升 1.x 另行公告 |

## 实际含义

1. **升级同 z 版本（如 0.11.0 → 0.11.1）**：放心升级，代码不需改动。
   若发现必须破坏 API 的修复，会提升 y 版本而非违背 z 承诺。

2. **升级 y 版本（如 0.11 → 0.12）**：**先查 [`CHANGELOG.md`](../CHANGELOG.md)
   对应版本的「破坏性变更」小节**。它列出：改了什么、旧写法是什么、
   新写法是什么。

3. **0.x 阶段无长期弃用期**：与 Zig 一致，不搞「deprecated 两个版本再删」。
   破坏即破坏，但**必须进 Changelog**——这是唯一的正式告知渠道。

## 破坏性变更如何被记录

- 每次破坏性变更在 `CHANGELOG.md` 对应版本下明确列出「破坏性变更」小节。
- 变更发生时同步更新 `doc/api.md`（新写法）与 `doc/example.md`（示例）。
- 历史踩坑与决策记录见 `doc/special.md`，不随 Changelog 重复。

## 为什么暂不承诺 1.x

- 框架仍在快速演进。
- 承诺 1.x 稳定需要 API 冻结 + 完整迁移测试，过早承诺只会让框架不敢改。
- 与 Zig 同策略：用「y 破坏必记录」换取「0.x 仍敢演进」。
